# Лидия: Безопасный Вход — Клиентская защита авторизации

Русскоязычное руководство по архитектуре ядра `js/main.js` модуля **Lydia CMS: SecureGate**.

## 🏗️ Подробный технический разбор архитектуры кода

Вся логика библиотеки построена на стандартах ES3/ES5 для обеспечения 100% совместимости со старыми браузерами (включая IE8) и минимизации нагрузки на бэкэнд CMS Lydia.

### 1. Изоляция области видимости (IIFE)
Код обернут в самовызывающуюся функцию `(function() { ... })();`. Это защищает глобальную область видимости от засорения. Переменные внутри модуля скрыты от потенциальных XSS-атак. Наружу экспортируются только безопасные интерфейсы `LydiaSecureGate` и `requireScript`.

### 2. Кроссбраузерный метод `protect`
```javascript
if (element.addEventListener) { ... } else if (element.attachEvent) { ... }
```
Позволяет безопасно вешать перехватчики событий как в современных браузерах (`addEventListener`), так и в старых движках Internet Explorer (`attachEvent`), предотвращая утечки памяти при циклическом рендеринге страниц.

### 3. Алгоритм перехвата и ветвления событий
При срабатывании защищенного действия (клик или отправка формы через Enter) метод `_handleEvent`:
1. Наглухо блокирует стандартное поведение браузера через `preventDefault()` (данные не отправятся по http).
2. Опрашивает локальное свойство `window.location.protocol`.
3. **Если HTTPS активен:** Сразу возвращает управление вашей функции (`safeCallback()`).
4. **Если активен HTTP:** Запускает скрытый фоновый опрос сервера.

### 4. Оптимизированный фоновый пинг (`_pingServer`)
```javascript
xhr.open("HEAD", checkUrl, true);
```
Для проверки поддержки сервером HTTPS используется асинхронный HTTP-метод **HEAD** вместо тяжелого **GET**. Сервер CMS Lydia не тратит ресурсы процессора на генерацию HTML-страницы или запросы к базе данных. Он мгновенно возвращает только служебные заголовки (размер ответа — несколько байт).

* **Результат успеха (статус > 0):** Браузер выполняет команду `location.replace()`. Пользователь бесшовно переводится на защищенную версию.
* **Результат провала (статус 0 / ошибка):** Вызывается жесткая блокировка. Блок с ID `secure-critical` получает свойство `display: block`, а форма скрывается.

### 5. Безопасный асинхронный загрузчик (`requireScript`)
Реализует концепцию **Lazy Loading** (ленивая загрузка). Защищенные файлы (например, `js/auth.js`) физически не запрашиваются у сервера, пока соединение не признано безопасным.
* Метод отслеживает как стандартный `script.onload`, так и специфичный для старого IE `script.onreadystatechange`.
* В случае блокировки скрипта плагином **NoScript** или сетевой ошибки, срабатывает `script.onerror`, предотвращая зависание интерфейса.
* Все динамические скрипты принудительно встраиваются в самый конец тега `<body>`, строго после футера, сохраняя чистоту DOM-дерева.
